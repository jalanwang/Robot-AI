## 📑 섹션별 상세 요약

### 1. Intro: C++와 메모리 관리의 철학
- C++은 개발자에게 하드웨어에 대한 **직접적인 제어권**을 부여합니다.
- **Performance**: 추상화 계층을 줄여 메모리에 직접 접근함으로써 최적의 성능을 냅니다.
- **Responsibility**: 제어권이 큰 만큼 메모리 해제 등 관리 책임도 개발자에게 있습니다.

### 2. 변수와 메모리의 본질 (Lecture 02)
- **변수명(Variable Name)**: 메모리의 특정 **물리적 주소**에 사람이 이해하기 쉽게 붙인 **별명(Alias)**입니다.
- **심볼 테이블(Symbol Table)**: 컴파일러는 내부적으로 변수 이름과 해당 주소를 매핑하여 관리하며, 실행 시에는 이름 대신 주소로만 통신합니다.
- **메모리 구획 (Process Address Space)**:
    - **Code (Text)**: 실행할 기계어 명령어가 저장된 읽기 전용 영역.
    - **Static / Global (Data & BSS)**: 
        - **Data Segment**: 초기화된 전역 변수 및 정적 변수.
        - **BSS Segment**: 초기화되지 않은 전역 변수 (프로그램 시작 시 0으로 초기화됨).
        - **특징**: 프로그램 시작 시 할당되고 종료 시에만 해제됩니다. 데이터의 수명이 프로그램 전체에 걸쳐 있습니다.
    - **Heap**: 런타임에 동적으로 할당되는 영역 (위에서 아래로 성장).
    - **Stack**: 함수 호출 시 지역 변수와 제어 정보가 저장되는 영역 (아래에서 위로 성장).

### 3. 변수 타입 상세 #1 (Lecture 03)
- **메모리 해석(Interpretation)**: 같은 비트 패턴이라도 타입에 따라 값이 다르게 읽힙니다. 타입은 데이터를 보는 안경입니다.
- **초기화와 쓰레기 값(Junk Value)**: 성능을 위해 스택을 0으로 밀지 않으므로, 선언 시 반드시 초기화해야 합니다.
- **포인터 연산**: `ptr + 1`은 타입의 크기(`sizeof`)만큼 점프합니다.

### 4. 변수 타입 상세 #2 (Lecture 04)
- **부호 비트(Signed/Unsigned)**: MSB(최상위 비트) 해석에 따른 2의 보수법 적용 여부.
- **엔디언 (Endianness)**: Little Endian(하위 바이트 우선) vs Big Endian(상위 바이트 우선).

### 5. 스택 메모리 깊이 알기 (Lecture 05)
- **스택 프레임(Stack Frame)**: 함수 호출 시 생성되는 블록(매개변수, 복귀 주소, 지역 변수 포함).
- **LIFO 효율성**: 스택 포인터 레지스터 이동만으로 할당/해제가 이루어져 매우 빠릅니다.

### 6 & 7. 힙 메모리 활용 및 Safe C++ (Lecture 06 & 07)
- **new/delete vs malloc/free**: `new/delete`는 메모리 할당뿐 아니라 **생성자/소멸자**를 호출하여 객체의 생명주기를 관리합니다.
- **힙 메모리를 사용하는 핵심 이유 3가지**:
    1. **수명(Lifetime) 관리**: 함수가 종료(Stack pop)되어도 데이터가 사라지지 않고 유지되어야 할 때 사용합니다.
    2. **가변 크기(Dynamic Size)**: 런타임에 입력 값에 따라 배열의 크기 등이 결정되어야 할 때 필수적입니다.
    3. **대용량 데이터(Large Data)**: 스택은 공간이 매우 협소(보통 1~2MB)하므로, 큰 데이터를 다룰 때는 광활한 힙 영역을 사용해야 합니다.
- **Safe C++ 스타일의 필요성**:
    - Raw 포인터(`new/delete`)는 **Memory Leak(해제 망각)**, **Dangling Pointer(이미 해제된 곳 참조)**, **Double Free(중복 해제)** 등의 치명적인 오류를 유발합니다.
    - **RAII (Resource Acquisition Is Initialization)**: 자원 획득을 객체의 초기화와 연동하여, 객체가 스택을 벗어날 때 자원이 자동으로 해제되게 설계해야 합니다.
    - **Smart Pointers**: Modern C++에서는 `std::unique_ptr`, `std::shared_ptr`를 사용하여 메모리 관리 실수를 원천 차단합니다.

### 8. 메모리 릭과 프로세스 (Lecture 08)
- **Memory Leak**: 힙 주소를 담은 포인터를 잃어버려 해제 불가능한 상태가 되는 현상입니다.
- **Valgrind (메모리 디버깅 도구)**:
    - **역할**: 프로그램 실행 중 발생하는 메모리 누수(Leak), 잘못된 메모리 접근(Invalid Access), 미초기화 변수 사용 등을 탐지합니다.
    - **사용법**: `valgrind --leak-check=full ./executable` 명령을 통해 상세한 누수 지점(파일 이름 및 라인 번호)을 확인할 수 있습니다.
    - **중요성**: 대규모 프로젝트에서 수동으로 찾기 힘든 미세한 누수를 잡기 위한 필수 도구입니다.
- **가상 메모리(Virtual Memory)**: 프로세스마다 독립적인 주소 공간을 제공하여 시스템 안정성을 높입니다.

### 9. 결론: 왜 힙인가? (Lecture 09)
- 힙은 **유연성**과 **영속성**을 제공하지만, 관리가 까다롭습니다. 따라서 **스마트 포인터와 STL 컨테이너(vector 등)**를 적극 활용하는 것이 최신 C++의 정석입니다.
